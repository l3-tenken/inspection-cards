# 設定ファイルの作り方 (AI への頼み方と、AI が従う手順)

点検カードの設定ファイル (点検表ごとの JSON) を、AI (Claude Code・ChatGPT・Copilot など) に作ってもらう・直してもらうための手順書。
前半は **頼む人 (利用者) 向け**、後半は **作業する AI 向け** の手順。どの AI もこのファイルに従う。

---

## A. 頼み方 (しばらく間が空いて忘れたら、ここだけ読む)

### 用意するもの (毎回添付する)

| もの | 新しい品種 | 直し (使ってみて問題があった) | 改訂 (点検表が新しい版になった) |
|---|---|---|---|
| 点検表 (.xlsx / .xlsm) | ○ 補足を書き足したもの | ○ 実際に使ったものでよい (補足があれば書き足す) | ○ 新しい版 (補足を書き足したもの) |
| 今の設定ファイル (.json) | 似た品種のものがあれば | ○ | ○ |
| 作業まとめ (.md) | あれば | ○ | ○ |
| 前の版の点検表 | - | - | あれば |
| スクリーンショット | - | あれば (問題の画面) | - |

- 設定ファイル・作業まとめ・点検表は **非公開の資料**。GitHub には置かず、自分で保管しておく (AI から送られてきたら上書き保存する)。
- 作業まとめを無くしたら、無しで頼んでよい (AI が新しく作る)。

### 補足の書き方

点検表の **空いている列** (記録の右側) の 1 行目あたりに「補足」と書き、その列の各行に指示を書く (書き方は下の「C. 補足の書き方」)。
補足のない行は、AI が今の設定 (または似た品種) に合わせる。

### 頼む文 (そのまま貼る)

**Claude Code (いちばん確実。アプリの直しと公開までできる)** — このリポジトリ `l3-tenken/inspection-cards` を開いたセッションで:

```
設定ファイルを作って (または: 直して)。添付: 点検表 / 設定ファイル / 作業まとめ
(直しのときは、どの項目がどうだったかを 1 行ずつ)
```

**ChatGPT・Copilot (設定ファイルを作るところまで)** — 次の文に、ファイルを添付して送る:

```
点検カード (https://github.com/l3-tenken/inspection-cards) の設定ファイルを作ってください (または: 直してください)。
手順は次のファイルに従ってください (読めなければ添付したものを使ってください):
- https://github.com/l3-tenken/inspection-cards/blob/main/docs/設定ファイルの作り方.md (手順)
- https://github.com/l3-tenken/inspection-cards/blob/main/README.md (設定ファイルの項目の一覧)
- https://github.com/l3-tenken/inspection-cards/blob/main/dev/check_profile.py (確認用。Python で実行して警告 0 件にする)
添付: 点検表 / 設定ファイル / 作業まとめ
```

- AI がリンクを読めないときは、上の 3 つのファイルを GitHub の画面で開き、「Raw」(またはダウンロード) から保存して一緒に添付する。
- 何度も使うなら、ChatGPT はプロジェクト (または GPT)、Copilot はエージェントを作り、上の 3 つのファイルを「知識」に入れ、
  上の頼む文を「指示」に入れておくと、次からはファイルを添付して「設定ファイルを作って」だけで済む
  (画面の名前は変わることがある。「ファイルを添付して指示を保存しておく機能」を探す)。
  職場の Microsoft 365 Copilot のエージェントは [Copilotエージェントの作り方.md](Copilotエージェントの作り方.md) に、
  そのまま貼る指示 (必要なファイルの案内 → 確認と質問 → 作成 の順に進める) と作り方がある。
- ChatGPT・Microsoft 365 Copilot は **アプリの直しはできない**。「設定では直せない」と言われたら、Claude Code か GitHub Copilot に頼む
  (GitHub Copilot に頼むときは「E. GitHub Copilot にアプリの直しを頼むとき」の注意を読む)。

### 受け取ったら

1. 送られてきた設定ファイル・作業まとめを保管する (前のものに上書き)
2. iPad のアプリで「設定ファイルを読み込む」→ 点検表を開き、注意 (「点検表が改定されたため…」) が出ないか、カードの並びを見る
3. おかしなところは、スクリーンショットを付けて同じように頼む

## B. AI の手順 (作業する AI はこの順に進める)

### 0. 守ること

- このリポジトリは **公開** されている。点検表の名前・項目名・行・設備名は、リポジトリ (コード・コミット・PR) に書かない。
- 設定ファイル・作業まとめ・点検表は **非公開**。作ったものは利用者に **ファイルで渡す** (GitHub に上げない)。
- 添付された点検表の補足の列 (指示) は実物にはない。確認に使うときは、補足の列を消したダミーを作る (残っていると前回の記録とみなされる)。
- 推測で埋めない。補足が読み取れない・決まりにない書き方のときは、こちらの判断で決めて「こちらの判断」として作業まとめに書くか、質問する。
- 設定ファイルの項目は README.md の「設定ファイル」の一覧にあるものだけを使う。ない書き方を作らない。

### 1. 読む

- README.md の「設定ファイル」(全項目の説明)
- 添付された設定ファイル・作業まとめ (前回までの判断)
- 点検表: 対象のシート、列の並び (区分・項目名・補足・単位・設定値・最小・判定種別・最大・備考・桁数)、
  基本情報 (日付・時間・担当) の行、項目の始まりと終わり、記録の列 (どこから始まり、最後の記録はどこか)、補足の列

### 2. 洗い出す

- 直し・改訂: 新旧の点検表 (または今の設定と点検表) を突き合わせ、行の増減・キー (点検順) の振り直し・項目名の変化を一覧にする。
  設定の行の指定はすべて「キー `no` + 項目名 `name` + 控えの行番号 `_row`」なので、変わった行は全部直す
- 補足の列の指示を 1 行ずつ「C. 補足の書き方」で設定に置き換える
- 補足のない行は、今の設定 (なければ似た品種の設定・「D. いつもの判断」) に合わせる

### 3. 作る

- JSON の形は README.md と今の設定ファイルに合わせる (`"type": "inspection-cards-profile"`, `"version": 1`)
- 行の指定には必ず `no`・`name`・`_row` を書く (`name` は項目名の一部でよいが、同じキーの行と区別できるだけ書く)
- `headerCheck` は対象シートの列の見出しセルを書く (シートは名前ではなくこの見出しで選ばれる)
- `fileMatch` はファイル名に必ず含まれる文字 (品種名など)

### 4. 確かめる (必ず行う)

```
python dev/check_profile.py <設定.json> <補足を消したダミー.xlsm> [--sheet シート名]
```

- **警告 0 件** にする (警告が 1 件でもあると、アプリは「点検表が改定されたため…」の注意を出す)
- 「新しい記録の列」が、次に書き込むべき列になっているか (前もって値を入れてある列があるなら `presetRows`)
- カードの一覧で、入力方法 (数値・選択・文字・自動計算)・選択肢・任意・対象外・一覧・列分け・条件の振り分けが、補足どおりか
- Python が使えない AI は、このスクリプトの代わりに「行の指定が点検表の行と合っているか」を表にして利用者に見せる

Claude Code はさらに、アプリの画面で 読み込み → 入力 → 書き出し を通し、元ファイルとの違いが書き込んだ列だけか確かめる:

```
python dev/serve.py 8765 --ext <ダミーのフォルダ> --out <書き出し先>   # 別に起動しておく
node dev/e2e.js <設定.json> <ダミー.xlsm> <書き出し.xlsm> --sheet <シート名> --prev
python dev/verify.py <ダミー.xlsm> <書き出し.xlsm> <列名> <シート名> <前回の列名>
```

### 5. 設定で直せないとき

- アプリの動きを変えないと直らない問題 (書き出したファイルがおかしい、設定の項目にない動きが必要など) は、
  ChatGPT・Microsoft 365 Copilot は「設定では直せない。Claude Code か GitHub Copilot に頼んでください」と理由を添えて伝え、そこで止める
- Claude Code は CLAUDE.md に従ってアプリを直し、PR を作って `main` にマージする (マージで公開される)。
  新しい設定の項目を作ったら README.md と `dev/check_profile.py` も直す

### 6. 渡す

- 設定ファイル (.json) と作業まとめ (.md) を **ファイルで** 渡し、保管を頼む
- 作業まとめには、品種ごとの節に次を追記する (次に頼むとき、これを読めば経緯が分かるように):
  日付 / 頼まれたこと / 補足の指示とその置き換え先 / こちらの判断 (違えば直す) / 点検表側で気づいたこと / 確認したこと / 未確認のこと
- 返事には、変えたところの要約・こちらの判断・利用者が iPad で確かめること を短く書く

## C. 補足の書き方 (補足の列の書き方 → 設定の項目)

補足の文言は多少違ってもよい。意味が合うものに置き換える。

| 補足の書き方 (例) | 意味 | 設定 |
|---|---|---|
| `選択 A/B` / `A or B` / `A\|B\|C` | 選択式にする | `rowTypes` の `options` (`"A\|B"`) |
| `選択 A/B (A は押せない)` / `A はグレー` | 選択肢を見せたまま押せなくする | `rowTypes` の `disabled` |
| `選択` (選択肢が書いていない) | ON/OFF などのボタン | 前回の値が ON/OFF なら `choiceSets` で自動。なければ `rowTypes` |
| `数値` / `文字` | 入力方法の指定 | `rowTypes` の `type` |
| `不使用` / `対象外` / `入力しない` | カードにしない | `exclude` |
| `任意` / `空欄可` | 空欄でも未入力に数えない | `optionalRows` |
| `計算式` / `= 〇行 - △行` / `自動計算` | 入力せず計算し、Excel には式で書く | `formulaRows` (式は前回の記録の式か `formula`) |
| `式無し` / `直接入力` | 計算せず数値で入力 | 何もしない (数値になる。ならなければ `rowTypes`) |
| `一覧` / `まとめて表示` | 項目名と入力欄を 1 行にして縦に並べる | `compactRows` |
| `OS/DS で縦 2 列` / `左右に分ける` | 列分け表示 | `splitGroups` (項目名の末尾から取るなら `pattern`) |
| `見出し「〜」にまとめる` | 区分の見出しを付け直す | `sectionRows` |
| `〇〇を選択 → 選んだ側だけ表示` (巾など) | 選んだ値の単語を含む行だけ出す | `conditions` の `match.token` |
| `直前に 1系/2系 を選択` | ある行の前で選ばせ、選んだ側の行だけ出す | `conditions` の `rows` + `placeBefore` (+ 選んだ値を書く行は `writes`) |
| `〇〇の値の帯で振り分け` | 数値の帯で行を選ぶ | `conditions` の `match.band` |
| `ここに値があっても空欄探索の対象から除外` / `先の列まで値あり` | 前もって値 (式・「-」) を入れてある行 | `presetRows` |
| `必須` | 入力を求める | 何もしない (既定で必須) |

- 補足の列のほか、点検表のセルの **コメント** (メモ) に指示が書かれていることがある。
  記録の列のコメントの多くは現場のメモ (アプリの「前回メモ」に出る) なので、指示と区別する。迷ったら質問する

## D. いつもの判断 (補足がないときに AI が決めてよいこと)

これまでの品種で、利用者に確かめて決まった判断。違う点検表では違ってよいので、使ったら「こちらの判断」として作業まとめに書く。

- 項目名の末尾が OS / DS (左右) の対になっている行が続く → `splitGroups` で縦 2 列 (`"pattern": "(OS|DS)\\s*$"`)
- 似た項目が十数行並ぶ (区画ごとの温度・幅など) → `compactRows` で一覧表示。見出しが区分の列どおりだと分かれてしまうなら `sectionRows`
- 前回の記録の列に式が入っている行 → `formulaRows` (前回の式をずらして使う。行番号で書くなら `formula` の `{col}`)
- 記入例・前回の記録が「-」の行 (使っていない機器など) → `optionalRows` (任意)。先の列まで「-」が入っているなら `presetRows` も
- 判定種別が「設定±N」 → `kinds.tolerance` に「設定±」を入れる (設定値 ± N が管理幅になる)
- 判定種別が「参考」など、管理ではなく目安の値 → `kinds.reference` (外れても警告のみ)
- 前回の値が文字 (選択肢のような値) なのに数値入力になる行 → `rowTypes` で選択式
- 点検表の誤記らしいもの (項目名の OS/DS の取り違え・単位の列に数値など) は直さず、作業まとめの「点検表側で気づいたこと」に書く

## E. GitHub Copilot にアプリの直しを頼むとき

GitHub Copilot (コーディングエージェント) はこのリポジトリを直接直し、PR を作れるので、アプリの直しも頼める。
ただし Claude Code と違うところがあるので、次を守る。

**頼む人 (利用者) が守ること**

- **頼み事 (Issue・PR のコメント) は公開される。** 点検表・設定ファイル・作業まとめを添付しない。品種名・項目名・行番号も書かない。
  問題は「前もって式が入っている列に書き出すと、計算結果が入力前のまま」のように、一般的な言葉で書く
- Copilot は点検表の実物を見られないので、問題が分かるような **ダミーの説明** を添える
  (例:「記録の列の右に、先の列まで式が入っている行がある。式は 2 つのセルの差」)
- PR ができたら中身を確かめて **自分でマージする** (マージで iPad のアプリが更新される)。
  不安なときは、マージせずに Claude Code に「この PR を確かめて」と頼む
- 設定ファイルの直しは Copilot には頼まない (点検表を渡せないため)。設定ファイルは Claude Code・ChatGPT・Microsoft 365 Copilot に頼む

**頼む文 (Issue に書いて Copilot に割り当てる)**

```
点検カードのアプリを直してください。AGENTS.md と CLAUDE.md の決まりに従ってください。
問題: (一般的な言葉で。点検表の名前・項目名は書かない)
期待する動き:
確認: 問題を再現するダミーの点検表を作って確かめ、ダミーはコミットしないでください。
```

**Copilot が守ること**

- `CLAUDE.md` の「守ること」に従う (特に: 実際の点検表の名前を書かない、`app/` を変えたら `app/sw.js` の `VERSION` を上げる、
  書き出しは対象シートの XML だけを変える)
- `app/profile.js` などの規則を変えたら `dev/check_profile.py` も直す。新しい設定の項目は README.md とこの手順書の「C.」に足す
- 確認はダミーの点検表で行う (コミットしない)。ブラウザ (Playwright) が使えるなら `dev/e2e.js`・`dev/check_app.js`、
  使えなければ少なくとも `dev/check_profile.py` と、書き出しの処理を Node などで呼んで `dev/verify.py` で比べる。確認できなかったことは PR に書く
- `main` に直接 push しない (PR を作って利用者のマージを待つ)
